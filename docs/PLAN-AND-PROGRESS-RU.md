# Deskflow для Windows + Linux: план и журнал

## Цель

Собрать собственную совместимую сборку Deskflow для двух машин: Windows PC `phantomlancer` и Linux Mint laptop `diffulinux`. Сохранить сетевую связность, текущие имена компьютеров, сертификаты и настройки. Сборки выполнять только через GitHub Actions. Не устанавливать CMake, Qt, MSVC или другие build-зависимости на пользовательские ПК.

## Текущая исходная точка

- База форка: Deskflow upstream `master`, commit `80221f0f7b7e` (18.11.2026).
- Исходный форк: `phantom-lancer/deskflow`, default branch `master`.
- Ветка работы: `work/file-transfer`.
- Исследуемый код: `Eyad-Alqaysi/hopflow`, commit `e9026e40833c`.
- Первый CI-перенос остановился на конфликтах cherry-pick второго коммита Hopflow. Это не ошибка установленного Deskflow и не проблема локального Commander. Исходники продукта ещё не были успешно перенесены.

## Что найдено в Hopflow

| Возможность | Состояние по исходникам |
| --- | --- |
| Передача файлов по протоколу Hopflow | Реализован отдельный файловый транспорт с манифестом, чанками, подтверждениями и временной staging-папкой |
| Копировать файлы и вставлять на другом ПК | Реализовано для Windows/macOS; Linux явно исключён из file-clipboard paste |
| Перетащить файл через границу экранов | Реализован механизм drag offer/drop; Windows использует GUI drop-probe, macOS читает drag pasteboard |
| Получать сброшенные файлы на Linux | Маршрутизатор допускает Linux-получателя Hopflow, но это нужно проверить на нашей сборке |
| Отправлять drag-файлы из Linux | В исходниках Hopflow не найден эквивалент платформенных хуков для Linux `EiComputer`; не считать реализованным до разработки и теста |
| Трансляция экрана и звука | Отдельная подсистема. В первую версию не включать, чтобы не добавлять постоянную нагрузку и риски для задержки мыши |
| Ctrl/Cmd swap | В основном относится к macOS; для Windows + Linux не приоритет |

Для файлового протокола используется отдельная версия `1.100` с сообщениями `H...`. Оба наших компьютера должны работать на сборках с этой поддержкой. Обычный Deskflow без Hopflow-протокола не должен получать такие сообщения.

## Принципы реализации

1. Сначала сохранить весь текущий функционал Deskflow и проверить совместимость конфигураций.
2. Переносить Hopflow небольшими логическими частями, сохраняя upstream-изменения Deskflow при разрешении конфликтов.
3. После переноса запускать GitHub Actions для Windows x64 и Linux. Не считать успешный cherry-pick успешной сборкой.
4. Отдельно закрыть Linux → Windows и Windows → Linux: файловый clipboard и native drag должны проверяться в обоих направлениях.
5. Передачу выполнять в фоне, с ограничением размера, chunk flow-control и staging. Не добавлять частый polling или тяжёлую работу в обработчики движения мыши.
6. Не включать screen/audio streaming в базовую сборку.
7. Для Linux сделать тёмное оформление. Для Windows - более аккуратное Fluent/WinUI-inspired оформление на существующем Qt, без замены UI-стека на WinUI 3.
8. Добавить понятные настройки глобальных мультимедийных клавиш и блокировки курсора. Настройки должны храниться в конфиге Deskflow, а не в исходниках или CI secrets.
9. Не публиковать в репозитории пользовательские конфиги, IP-адреса, имена хостов, приватные ключи и TLS-сертификаты. Сейчас репозиторий публичный, поскольку GitHub fork публичного репозитория нельзя просто превратить в приватный.

## Правила установки и отката

- До установки сохранить резервные копии текущих пользовательских настроек и сертификатов отдельно от Git.
- Не заменять конфиги или сертификаты новыми файлами из пакета.
- Устанавливать только после успешных Windows/Linux CI-сборок и проверки артефактов.
- Сначала обновить одну сторону, проверить соединение и базовое управление, затем вторую.
- Сохранить установщик Deskflow 1.27.0 для быстрого отката.
