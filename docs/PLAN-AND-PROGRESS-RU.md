# Deskflow Personal: план и журнал

## Цель

Сделать совместимую сборку Deskflow для Windows и Linux с передачей файлов перетаскиванием, настраиваемыми глобальными F6/F7/F8, тёмным Linux UI и аккуратным Fluent-inspired Windows UI.

Сборки и релизы выполняются через GitHub Actions. На пользовательских компьютерах не устанавливаются компиляторы, Qt, CMake, MSVC или другие зависимости для сборки.

## Исходная точка

- Репозиторий: `phantom-lancer/deskflow`.
- Рабочая ветка: `work/file-transfer`. Основная ветка `master` не меняется.
- База: Deskflow upstream commit `80221f0f7b7e` от 18.11.2026.
- Файловый транспорт взят из открытого проекта `Eyad-Alqaysi/hopflow`.
- Репозиторий публичный: GitHub не позволяет превратить форк публичного репозитория в приватный без отделения от upstream. Конфиги, адреса, TLS-сертификаты и приватные ключи в Git не добавляются.

## Что реализовано в исходниках

### Передача файлов

- Перенесён протокол Hopflow 1.100 и маршрутизатор передачи файлов.
- Реализованы manifest, передача чанками, flow control, проверка путей и лимита объёма.
- Добавлены drag-probe для Linux-клиента и обработка завершения drag.
- Полученные файлы сохраняются в `Downloads/Deskflow`.
- Размер чанка уменьшен с 256 до 64 КиБ, окно - с 32 до 8 чанков. Максимальный объём неподтверждённых данных снижен с 8 МиБ до 512 КиБ, чтобы ограничивать синхронную дисковую работу внутри event loop.
- Передача файлов через clipboard на Linux не заявляется: в исходном Hopflow она реализована для Windows/macOS. Наша цель на этом этапе - обычное перетаскивание файлов, в том числе PNG/JPG.

### Медиаклавиши

- Добавлена группа настроек в конфигурацию сервера при использовании внешнего `deskflow-server.conf`.
- F6 - предыдущий трек, F7 - play/pause, F8 - следующий трек.
- Можно отправлять команды всем компьютерам или выбрать отдельные имена.
- Глобальный hotkey регистрируется на основном компьютере; указанные назначения определяют получателей команды.
- При изменении внешнего конфига меняются только три строки F6/F7/F8 внутри `section: options`. Другие параметры, раскладка экранов и существующие lock-cursor hotkeys сохраняются.
- Перед изменением внешнего файла создаётся локальная резервная копия `.before-media-hotkeys.bak`.

### Интерфейс

- Linux: тёмная QSS-тема с палитрой Fusion.
- Windows: Fluent-inspired стили на существующем Qt Widgets, светлый/тёмный вид выбирается по системной теме Windows.
- Не добавлялись новые runtime-библиотеки или фоновые процессы.
- App ID, MSI upgrade identity и существующая конфигурационная структура Deskflow сохранены.

## Важные ограничения

- Успешная сборка не гарантирует отсутствие регрессий в реальном окружении.
- Linux drag-and-drop требует проверки на фактическом типе сессии. Перемещение прозрачного drop-probe может быть ограничено Wayland; для XFCE/X11 этот путь ожидаемо проще.
- Передача файлов на Linux должна иметь доступ к папке загрузок Flatpak. В манифест добавляется только `xdg-download`, не весь домашний каталог.
- Перенос экрана и звука не включается: это отдельная тяжёлая подсистема.
- Нельзя обещать абсолютно нулевую задержку мыши; её нужно проверить во время реальной передачи большого файла.

## Установка и откат

1. До обновления создать локальные резервные копии конфигураций и TLS-данных. Эти копии остаются вне Git.
2. Не заменять пользовательские конфиги или сертификаты файлами из пакета.
3. Сохранить установщик старой версии для Windows и возможность возврата к текущей Flatpak-сборке.
4. Обновлять обе стороны согласованно, затем проверить соединение и ввод.
5. Только после проверки файловой передачи и управления считать сборку готовой к повседневному использованию.
