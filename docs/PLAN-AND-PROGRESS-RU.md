# Deskflow: план и журнал разработки

## Цель

Подготовить совместимую сборку Deskflow для Windows и Linux с сохранением существующих функций, пользовательских настроек и TLS-данных. Сборки выполнять через GitHub Actions. Не устанавливать компиляторы, Qt, CMake или другие build-зависимости на пользовательские устройства.

## Исходная точка

- Основа: Deskflow upstream `master`, commit `80221f0f7b7e` (18.11.2026).
- Рабочий репозиторий: `phantom-lancer/deskflow`.
- Рабочая ветка: `work/file-transfer`.
- Внешний проект для файлового транспорта: `Eyad-Alqaysi/hopflow`.
- Основная ветка `master` не изменялась.

## Исследование Hopflow

Hopflow добавляет протокол передачи файлов, маршрутизатор, chunked transfer, временную staging-папку, ограничения размера и интеграцию с обычным copy/paste и drag-and-drop.

Ограничения исходного Hopflow:
- Передача файлов через clipboard реализована для Windows и macOS.
- Linux пока не умеет передавать файлы как clipboard-файлы: его `PortalClipboard` поддерживает изображения и текст, но не `text/uri-list`.
- Linux как получатель drop поддерживается маршрутизатором, однако полный сценарий в обе стороны требует отдельной Linux-интеграции.
- Drag detection для Linux в Hopflow не реализован в `EiComputer`.
- Screen/audio streaming не включается: это отдельная тяжёлая подсистема и не нужна для обмена файлами.

## Текущая проверка

Первая проверка на GitHub выявила две проблемы:
1. CMake не находил четыре файла `CtrlCmdSwap`; они добавлены в рабочую ветку.
2. Первые Linux configure/Flatpak job завершились до компиляции из-за отсутствовавших файлов. Первый Windows job был отменён новым push во время установки зависимостей. Эти результаты не означают, что приложение собрано или протестировано.

Следующий GitHub Actions run должен проверить уже исправленный состав исходников:
- Windows x64: configure, build, unit tests, MSI.
- Linux x86_64: configure, build, unit tests.
- Linux Flatpak: bundle для существующего app-id Deskflow.

Успешный импорт исходников не считается успешной сборкой. Установка на устройства не начнётся до успешных сборок и проверки артефактов.

## Принципы реализации

1. Сохранять существующие app-id, MSI upgrade GUID, сетевой протокол и пользовательские настройки, насколько это совместимо с новой версией.
2. Не публиковать конфиги, IP-адреса, имена устройств, сертификаты, приватные ключи или иные локальные секреты.
3. Передачу файлов выполнять отдельным транспортом с лимитами, проверкой путей и отменой. Не выполнять дисковые операции в обработчиках движения мыши.
4. Реализовать Linux file clipboard и Linux drag-source отдельно, затем проверить обе стороны передачи.
5. Не менять обработчики mouse motion без конкретной необходимости и измеримой проверки задержки.
6. Linux UI: аккуратная тёмная тема. Windows UI: современный Fluent/WinUI-inspired вид на текущем Qt, без тяжёлой замены UI-стека.
7. Добавить понятные настройки глобальных мультимедийных клавиш и блокировки курсора.
8. Не включать screen/audio streaming.
9. Публиковать релизы только после проверки Windows/Linux CI и тестов.

## Правила установки и отката

- До установки создать локальные резервные копии пользовательских настроек и TLS-данных отдельно от Git.
- Не заменять конфиги или сертификаты файлами из сборки.
- Сначала проверить обновление одной стороны, затем второй.
- При регрессии восстановить прежнюю версию и настройки.
